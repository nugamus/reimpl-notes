# Editions: what the engine does differently for the CD and ISO versions (Ring)

The engine is written from the DVD edition (`RING_DVD.EXE`, VC6, 1999-09-14). This spec says
what changes for the **CD version** (6 discs, Borland `ring.exe`) and the **ISO version** (4
discs, VC6 `RING.EXE`, 1999-06-09). Evidence: E-0300..E-0314. Addresses: DVD unless noted.

## Summary

The three EXEs run the same game: the ISO's zone set-ups are the DVD's call for call once
file names are mapped, its zone handlers differ only in file names and a handful of details
(below), and the CD's set-ups differ in four places (E-0303, E-0304). What differs for the
engine is mostly **data naming and layout**. In priority order the engine must:

1. map the DVD's file names to the CD/ISO names (`notes/media-names.tsv`, "Names");
2. read the CD/ISO folder layout from one merged folder ("Discs and folders");
3. offer English, French and German only, and read SY's archive per language ("Languages");
4. per edition: the game-over pictures (ISO), New Game's AS entry (ISO plays the intro);
5. optionally (parity, Q-0101/Q-0100): the ISO's and CD's own handler details.

The engine keeps the DVD's game logic for all editions; the logic differences listed under
"Game logic" are the earlier builds' and can be kept as DVD behaviour (Q-0101).

## Names

The DVD renamed media to numbers; the CD and ISO keep descriptive names (E-0300). The table
`engines/ring/notes/media-names.tsv` (generated by `engines/ring/tools/namemap.py`) has one
row per DVD file whose name differs: `zone folder dvd name cd_discs iso_discs paired`, names
lower case with extension. Folders: `pla` (videos), `sound` (also `sound/<lan>`), `dia`
(also `dia/<lan>`: `.dia` subtitles, `.dan` lip sync), `image`, `visual`.

- 1,420 rows: 464 videos (442 on the CD/ISO discs, 22 named by their code only), 484
  sounds, 454 dialogue files, 10 AS pictures (`asv01.bma` = `ass01n01_v01.bma`,
  `asp01l01.bma` = `ass01n01p01l01.bma`, ...), 8 SY list pictures (`up_gun.tga` =
  `larup_gun.tga`, `down_*` = `lardown_*`, `load_*` = `larload_*`).
  DVD numbers are unique across zones, so a lookup by name alone is enough.
- A DVD number names the same file in every language (`DATA/NI/SOUND/ENG/1626.WAC` and
  `.../FRA/1626.WAC` both map to `cin_rh1_01.wac`).
- Names the code builds with `sprintf` follow the table: RH `rh_%d` / `rh_%d_l0` →
  `rhs00n0%dp01sa04` / `rhs00n0%dp01sa03_l0`, N2 `n2_%d%c` → `n2extn01p01a0%d%c` (the
  table has every expansion, e.g. `rh_2.cnm` = `rhs00n02p01sa04.cnm`; E-0304).
- `paired` = `code`: the file is on no CD/ISO disc; the name is the one their code uses
  in the DVD number's place. Two groups: the extra-language videos and subtitles (`1160` =
  `tr_wa_mm_2`, `1161` = `tr_wa_mm_3`, `1163` = `introm_2`, `1863`/`1864` =
  `tr_wa_a01_2/_3`, `1873`/`1874` = `tr_wa_a07_2/_3`, `1876`/`1877` = `tr_wa_a10_2/_3`;
  reached only in languages 4..10, "Languages"), and the rides missing from every edition
  (E-0097: `1723` = `rhs02n01_s01n01`, FO `1232`..`1262` = `fos00n08_s03n01`.., N2
  `1377`/`1385`; zone column empty).
- `md5-dup`: `fo_pla.wav` = `fo_planets_show.wav` (same bytes; no code names either).
- One CD video differs from its DVD file in 20 bytes of one frame (`1911` =
  `was03n01_s03n02_var2`, `paired` = `size`; E-0301).

**How to use it:** resolve every media name at file-open time (videos, sounds, subtitles,
lip sync, `PuzAddBgrImg`/`ObjPreAddImgToPuz` pictures, the SY list pictures of
`VisAddLisToPuz`), not in the zone code: the set-up table and zone code stay the DVD's. A
name with no row is the same in all editions (`logo.cnm`, node `.aqc`, archive members).
Lookups are case-blind: the CD/ISO discs mix cases (`data/WA/pla/WAS03N01_S03N02_VAR1.cnm`).

## Discs and folders

Every edition has the same tree, `DATA/<zone>/{PLA,NODE,DIA/<LAN>,SOUND[/<LAN>],IMAGE,VISUAL}`
and `DATA/<zone>.AT2`, `DATA/<LAN>/SY.AT2` (E-0008), spread over the discs (E-0302):

| Disc | CD version | ISO version |
|---|---|---|
| 1 | AS (image, node, pla), SY, `eng/fra/ger/sy.at2`, `as.at2` | programs, every `sound` and `dia` folder in eng/fra/ger, AS images, 13 AS videos, SY, RO (node, pla), `ro.at2`, `data/sy.at2` |
| 2 | English voices and subtitles of every zone, NI (node, pla), `ni.at2` | AS (image, node, pla), NI (node, pla), `as.at2`, `ni.at2` |
| 3 | French voices and subtitles, RH (node, pla), `rh.at2` | RH, WA (node, pla), `rh.at2`, `wa.at2` |
| 4 | German voices and subtitles, N2, RO (node, pla), `n2.at2`, `ro.at2` | FO, N2 (node, pla), `fo.at2`, `n2.at2` |
| 5 | FO (node, pla), `fo.at2` | — |
| 6 | programs, non-language sounds of every zone, WA (node, pla), `wa.at2` | — |

**Merged into one folder** (what a ScummVM user does: copy every disc's `data` into one
`DATA`), the only path with different contents on several discs is `data/cd.ini` (the
disc number); the ISO's 30 files on two discs are identical copies (E-0302). So the engine
reads one merged tree and ignores `CD.INI`. The original asks for a disc through
`GameZoneOnCD` (0x4312c0) and SY's insert-CD puzzle 90005 (`insertcd.bmp`) only when
`fl.ini`'s `CDPATH` is `CDROM` (app+0x1d); each EXE has its own zone → disc table (E-0309):
the DVD's and the CD's are the CD layout (SY any, AS 1, NI 2, RH 3, N2 4, RO 4, FO 5, WA 6),
the ISO's its own (RO 1, AS 2, NI 2, RH 3, WA 3, FO 4, N2 4). The engine never asks: no
disc check, no insert-CD screen, in every edition. `fl.ini` is the same in all three but
`CHECKCD` (0 DVD, 1 CD/ISO; E-0310), which the engine does not read.

Detection: the CD's game files are on disc 6 (`ring.exe` 712,192 B) and the data on discs
1..6; the ISO's on disc 1 (`ring.exe` 663,552 B). Detect on files every merged install has,
e.g. `data/as.at2` + `data/cd.ini` + one edition-specific file (CD: `data/sy/visual/larup_gun.tga`
with `data/wa/pla/was03n01_s03n02_var2.cnm` 5,144,408 B; ISO: the same video at 2,984,230
B, its re-encoding). The ISO's videos use the UNR codec (another spec).

## Languages

- The CD and ISO discs have English, French and German only: voices
  `DATA/<zone>/SOUND/<LAN>/`, subtitles and lip sync `DATA/<zone>/DIA/<LAN>/`, SY's archive
  `DATA/<LAN>/SY.AT2` (E-0302, E-0311). Offer exactly these three.
- The DVD and ISO EXEs register the same ten languages and channels (ENG 1/1, FRA 2/2, GER
  3/3, ...; E-0311, `spec/boot.md`); the CD EXE maps `fl.ini`'s `LANGUAGE` ENG, FRA, GER,
  ITA, SPA to 1..5 (else ENG) with no language table (0x411a13). For ENG/FRA/GER the
  video audio channel is the same in all three.
- The extra-language videos: AS entry 998 plays `INTROM_2` (DVD `1163`) for languages 4, 5,
  7, else `INTROM` (`1164`); AS entry 6 and WA's `tr_wa_mm`/`tr_wa_a01`/`tr_wa_a07`/
  `tr_wa_a10` rides take `_2` for 4, 5, 7, `_3` for 6 (SWE), else the base video (E-0305).
  With ENG/FRA/GER the base video always plays, so these names are never asked for on the
  CD/ISO.
- SY's archive: the CD's `eng/sy.at2` is byte-identical to the DVD's `ENG/SY.AT2` (fra and
  ger as well). The ISO's `eng/fra/ger/sy.at2` differ: they add `\image\end01.bmp` ..
  `end08.bmp` (game over, below) and redraw the menu pictures; its `data/sy.at2` (the DVD's
  English archive) lacks `end01..08`. On the ISO the engine reads `DATA/<LAN>/SY.AT2`
  (E-0308; which file the installed original reads is Q-0008/Q-0103).
- Texts: `aMes.ini` is the same for ENG/FRA/GER in all three; `aObj.ini` the same but
  object 40000 (no entry in the CD's file; French `Feu Force` and German `Vuurkracht` in the
  ISO's, DVD `Force d'feu`, `Feuerkraft`; E-0312). Read each edition's own files.

## New Game (AS entry)

`aApplication::Init` 0x431140 (New Game, `games/ring/docs/sy.md`) ends with `GoZone(7, n)`:
n = 999 (rotation 80001 and the timers) in the DVD's and the CD's `ring.exe`, n = 998 (the
intro film `INTROM` and its sound chain, then the same) in the ISO's `ring.exe`. Each
edition's `trailer.exe` is its `ring.exe` with the other value (E-0306). So on the ISO,
New Game plays the intro; on the DVD and CD it does not. The engine follows the edition
(a launcher option "intro on New Game" can default to the edition's behaviour).

## Game over (0x431190)

Same cases in all editions: NI causes 1..4, RH 1..4, N2 1..2 show a picture for 4,000 ms
(`0x401000(name, 0, 16, 4000, 2, load-from)`), then `StartMenu(0)`. The DVD and the CD show
`End.bmp` for all of them; the ISO picks per cause (E-0307):

| Zone | cause 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| NI (2) | `End01.bmp` | `End02.bmp` | `End03.bmp` | `End04.bmp` |
| RH (3) | `End05.bmp` | `End06.bmp` | `End02.bmp` | `End07.bmp` |
| N2 (8) | `End03.bmp` | `End08.bmp` | — | — |

## Set-ups (E-0303)

- **ISO**: every call of every zone's set-up is the DVD's, in order, with the same
  arguments once names are mapped; the only other difference is SY's `VisAddLisToPuz` list
  pictures (`larup_gun.tga`.., the table's `visual` rows).
- **CD**: as the ISO, except: SY's preference sliders 90105 and 90106 have no drag cursors
  (no `ObjSetActDraCur`/`ObjSetPasDraCur`); FO's Sieglinde (30102) accessibility #0 on
  rotation 30101 is the rectangle (924, 165)–(1207, 406) instead of (0, 0, 0, 0) (Q-0102);
  AS switches app+0x5d/0x58 through calls instead of stores (same values, same places).
  The engine keeps the DVD's table for every edition.

## Game logic (E-0304, E-0313, E-0314)

ISO against DVD, every zone handler of `spec/events.md` matched (1,454 of 1,793 DVD
functions; the rest is codec, file and runtime code). Besides file names:

- **WA** object click 0x437d60 (ISO 0x4405a0), object 0xc3b4: the DVD stops sound 51006
  (reason 0x400) only after the byte 50012 = 4 or > 4 branches; the ISO stops it after
  both tests whatever the byte.
- **NI** world score (float 90005, `games/ring/docs/ni.md`), object 10430 (0x28be,
  `unk_19` 1) in the object click 0x445c80 (ISO 0x44e460): putting object 10305 (0x2841)
  there adds 3 on the DVD, 5 on the ISO; taking it back (byte 10430 = 1, nothing in hand)
  subtracts 3 on the DVD, nothing on the ISO. The ISO's after-movability handler
  (0x451b20) adds 5 more after the ride `TR_NI_RH_Bshort`; the DVD's (0x449320) does not.
  On object 10450 (0x28d2) the two object clicks order the tests of byte 10106 (0x277a)
  and of the object in hand (10504, 0x2908) before the rides `NIS04N05_S04N06*`
  differently (Q-0101).
- **N2** sound-finished 0x435a00 (ISO 0x43e230): the control flow around byte 70014
  (0x1117e) differs (Q-0101).
- **AS** entry 998 and 6, **WA** rides: the language video choice above (names only).

CD against ISO: compiled by another compiler, its handlers compare only coarsely (strings
exactly, constants and API calls not; Q-0100). Strings the CD's code lacks or adds against
the ISO's (raw scan of both EXEs, E-0314): no `End01..08` (it shows `End.bmp`), no
`INTROM_2`/`TR_WA_*_2/_3` (no language choice for videos), its own save-list line
`%s  %02d.%02d.%d  %02d:%02d:%02d` and world names (`Nibelheim`, `Nibelheim II`, `Rock Of
Gods`, `Walkirien`, `Asteriod`, ...), window title `Ring Alpha 1.0`, `errSystemLog.txt`.
Saves: all three write `ArxSav 1.00` files tied to their own `ring.exe` (`spec/save.md`);
the engine's saves are its own and do not depend on the edition.

## Tools and generated files

- `engines/ring/tools/namemap.py` → `notes/media-names.tsv` (`--selftest`).
- `engines/ring/tools/ringemu.py --edition iso|cd` → `notes/calls-<edition>/<zone>_setup.jsonl`
  (DVD format, `addr` = the DVD callee, `exe_addr` the edition's) and
  `notes/calls-<edition>/diff-vs-dvd.md`.
- `tools/ghidra/scripts/ring_features.py` (PyGhidra, writes `build/ring-features/`) and
  `engines/ring/tools/handlers.py --edition iso|cd` → `notes/calls-iso/handlers-vs-dvd.md`,
  `notes/calls-cd/handlers-vs-iso.md`, `notes/calls-iso/string-pairs.tsv`.
- Order: `ringemu.py --edition iso`, `--edition cd`; `handlers.py --edition iso`, `--edition
  cd`; `namemap.py`; `ringemu.py --edition iso|cd` again (its diff reads the table).
- Decompiles of the differing handlers: `notes/decomp/editions/`.
