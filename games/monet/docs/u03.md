# U03: the street, the clown and the policeman

Everything U03's unit code (`U03.cpp`, vtable `0x004394e4`, E-0300) does on top of the
generic scene: the start (renames, hides, two looping positional sounds, three talkers),
the per-frame policeman walk along a path, the three click handlers (the clown's magic
trick, the policeman's salute, the cutscene at the clockmaker's) and the exit to **U33**
(not U04). Conventions are those of `u01.md` and `u02.md`: `RunFor`, `MoveTo`, `Say`,
suspend / resume, `Mnn`, "run node", slots. "Tick + render" is one animation tick and one
rendered frame with no message pump and no input (`RunFor(0)` without the pump).

`s` = 45 (`SCENE.BIN`: ambient 255/255/255, scale 45; `#CAMERA#` FOV 90, sphere radius 20,
Z offset 40, speed 7; E-0306), so eye height h = 67.5. U03 then sets sphere radius 30.5 and
Z offset 10.5 (below). No input hook (vtable `+0x40` is `Scene_HandleInput`), no load hook
(vtable `+0x10` is the generic `XScene_124`), and **no unit save chunk** (vtable `+8` /
`+0xc` are the generic ones; `save.md`).

**WalkPath, full form** (`FUN_00419620`, E-0161, E-0303): `WalkPath(start, target, yaw₀,
yaw₁, pitch₀, pitch₁, ms, callback)`. N = ⌊ms · fps / 1000⌋ (at least 1). The yaw
difference is taken the short way round (if yaw₁ − yaw₀ > π, yaw₀ += 2π; if < −π, yaw₁ +=
2π). Each step i = 1..N: eye := start + i·(target − start)/N, yaw and pitch += Δ/N, then `callback(eye, yaw, pitch, i, N)` if given, one
animation tick, render, emitter volumes, message pump. Finally eye := target, yaw := yaw₁,
pitch := pitch₁. `u02.md`'s `WalkPath(ms, target)` is this with yaw and pitch kept and
the ground-snap callback. U03 never passes the ground callback: its paths keep z.

**Ground point** `G(x, y, z)` (`U03::SnapToGround`, `0x00407050`): cast down from
(x, y, z) (`FindGroundBelow`, `movement.md`) and return (x, y, ground z + h).

**Face from P toward Q**: yaw and pitch of the unit vector Q − P (`X3d_Convert_To_Polar`,
the convention of `movement.md`); U03's walks use its yaw and force pitch π/2 (level).

## Every frame (`U03::UpdateFrameLogic`, `0x00405480`, E-0302)

Skipped entirely while a scene load is pending (app mode 1). Runs after the main loop's
animation tick and **before** rendering (it calls `Scene_RenderFrame` itself):

1. **The policeman walks the path** (`U03::FlicFollowPath`): if `follow` and node
   `*U03_09` is running: L := `*U03_09`'s local matrix (just sampled from `marche.a3d`);
   L := L · (Rz(π) · `*path`'s local matrix) (row vectors, `scene.md`); then set
   `*U03_09`'s global position to `*path`'s global position. So he walks the recorded route
   turned by 180°, the walk cycle on top.
2. Update the café and clown emitters' volumes from the eye (`sound.md` "Volume from
   distance"; only while their group plays). These two emitters are not in the scene's
   emitter list, so this is their only update: a scripted `RunFor` does not refresh them.
3. Render and present.

Scripted waits (`RunFor`, tick + render) do not run this hook: the policeman does not
follow the path during a cutscene.

### Animation transition (`U03::AnimateTransition`, `0x00406f90`, E-0305)

`AnimateTransition(a, b, n, fa, fb)` (fa, fb = −1: the clips' current frames): for i = 1..n:
one animation tick, then pose the object from clip a at frame fa and clip b at frame fb
blended with weight t = i/n (`X3d_Object_Animate_Transition`, all children), then
`RunFor(0)`. The blend rule is `animation.md` "Transitions" (E-0500). `RunFor(0)`'s own tick
re-poses the object from its active slot (a or b in every call here) before the render, so
the blend is never drawn: the player sees n frames of the active clip, with every running
node advancing twice per frame (E-0501).

## What the engine needs (for the implementer)

Existing primitives cover `RunFor`, `MoveTo`, `Say`, suspend, hide/show, collision per
object, cursor kinds, `runAction`, `setCondition`, inventory add, clip slot 1, autosave and
`gotoScene`. U03 also needs:

- **WalkPath with rotation and a per-step callback** (the general form above); U02's
  `walkPath` has neither.
- **A before-render unit hook** after the animation tick (the path follow must land in
  the frame it is drawn in); `Unit::afterFrame` runs after rendering.
- **Object transforms from unit code**: read an object's local matrix and global
  position, set its local matrix and global position after the animation pose.
- **Loading and releasing models at run time**: replace a hotspot's object with a new
  `.O3D` (plus a node from an `.A3D` bound by `XSceneAnim` rules), and load two extra
  models with their nodes for a cutscene, then remove them.
- **Re-registering a talker** under the same name with a new face object.
- **More clip slots**: named clips in slots 1..4 of one node (`salut` 2, `refelction` 3,
  `vers horloger` 4), switching the active slot, and slot lookup by name.
- **Animation transition** between two clips over N frames (`animation.md` "Transitions"; its pose is never drawn, E-0501).
- **Two extra emitters** (groups 5 and 6, absolute range 1000, looping), updated by the
  unit's frame hook, deletable. `sound.md`'s table says U03 plays on group 4: it plays on
  5 and 6 (E-0301).
- **Camera look-at from a point to a point** (`FUN_00419580`) and a direct FOV step.
- **Scene switch to `U33.X3D`** and U33's unit code (constructor `0x00407090`, E-0075;
  `u33.md`).
- **Tick + render without input** loops (U03 uses them inside the cutscene; `RunFor(0)`
  is close enough if input stays suspended).

## Engine notes

- Every scripted wait here keys on frames or on the voice group, not on wall time, except
  the trick's 9-s cap (step 8) and `RunFor(4500)` / `RunFor(7000)`: run those in logic time.
- The path follow uses the path node's own 4-fps clock; the route lasts 12.5 min, after
  which the policeman keeps walking in place at the route's end.
- A restore after the trick (E-0537): `ANIMATIONS` brings back the policeman's slot clips
